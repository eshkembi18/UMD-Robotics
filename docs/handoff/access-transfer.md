# Access Transfer Checklist

<p class="gr-meta">Maintainer: whole team · Last updated: [TEAM VERIFICATION REQUIRED] · Update before the end of every semester</p>

Do this **before** the outgoing team loses access. Missing one of these can cost the next team weeks.

!!! danger "Never record credentials"
    This page lists **who** administers each system and **what** to do. Never add passwords, tokens, keys, or account recovery details.

| System | Administered by now | Action | Done |
|---|---|---|---|
| GitHub org / repo | [TEAM VERIFICATION REQUIRED] | Add the new team as members. Make sure a **faculty member is an owner** | ☐ |
| GitHub Pages site | (follows the repo) | Confirm the site still deploys after the transfer | ☐ |
| Hugging Face org | [TEAM VERIFICATION REQUIRED] | Add the new team. Faculty member as admin | ☐ |
| NCSA Delta allocation | [TEAM VERIFICATION REQUIRED] | Ask the allocation manager to add the new users. Check the expiry date and remaining hours | ☐ |
| Jira | [TEAM VERIFICATION REQUIRED] | Transfer project admin | ☐ |
| Shared storage | [TEAM VERIFICATION REQUIRED] | Transfer ownership of folders | ☐ |
| Physical hardware | [TEAM VERIFICATION REQUIRED] | Hand over in person, check against the [inventory](inventory.md) | ☐ |
| Personal accounts used by mistake | — | Move anything owned by a personal account to an org account | ☐ |
